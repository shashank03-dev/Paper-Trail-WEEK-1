# Decisions

Short record of the calls made during the build and why. Longer reasoning lives in [docs/design.md](docs/design.md).

1. **The sheet is one SVG in millimetres.** One drawing serves the preview, print, the PDF export and the synthetic photos, and every coordinate the reader needs (checkbox rectangles, panel cells, fiducials) comes from the same `lib/zine/layout.ts`.
2. **Text is measured from real font metrics, not the DOM.** `scripts/gen-font-metrics.ts` reads the self-hosted font files and writes advance widths. `fitText` gives the same line breaks in the browser, on the server (where generated copy is checked before it's accepted) and in scripts. Kerning is ignored; boxes have a little slack.
3. **Fiducials live in the panel footers.** With the standard imposition every sheet corner lands in a panel-local bottom corner of pages 1, 2, 5 and 6, so every panel reserves a 12 mm footer and nothing collides.
4. **The cut runs across the middle two columns.** The brief's "between panels 3|2 and 7|8" conflicts with its own "centre two columns". The standard one-cut zine cuts the centre two columns (between 4|3 above and 7|8 below), so that's what's printed. `/fold-test` exists to catch any mistake.
5. **Route selection is deterministic.** Greedy insertion by interest ÷ added distance, nearest-neighbour ordering, then 2-opt. Gemma is given the route; it never chooses where you walk.
6. **Two-stage generation.** One structured plan call (temperature 0.2), then one call per copy panel (0.7–0.8). That gives the "printing press" reveal, makes "re-roll one panel" cheap, and keeps each schema small enough for a 4B model.
7. **`chatJSON` is the only way to ask for JSON.** JSON-schema `response_format` → tolerant JSON extraction → zod → semantic checks (grounding, fit) → retry with the exact problems (≤ 2) → caller falls back to a template. The path taken (`llm`, `llm-retry`, `replay`, `fallback`) is logged and shown in the UI.
8. **Ollama native `/api/chat` is behind a flag** (`LLM_OLLAMA_NATIVE=true`), for Ollama versions where `/v1` structured output misbehaves.
9. **Reading is per-panel plus OMR.** Four small focused crops beat one big photo for a small model; the checkbox ink measurement is a cheap, model-independent second opinion. Disagreements are surfaced, not hidden.
10. **The riddle is judged twice.** A lenient deterministic match (normalisation + Levenshtein against the answer and `acceptable[]`) decides clear cases; Gemma's verdict decides the rest.
11. **Client-side vision.** Fiducial detection, homography and warp run in the browser in plain TypeScript (no OpenCV). Only four cropped PNGs go to the model endpoint.
12. **Client-side PDF.** The SVG is rasterised at 300 dpi with fonts inlined as data URIs and placed on an exact-size page with pdf-lib. pdf-lib is loaded only when you click the button. Browser "Print → Save as PDF" is the vector option.
13. **Fonts are self-hosted, not Google Fonts.** Same families as the brief (Fraunces, Inter, IBM Plex Mono, Caveat), but no third-party request when the app opens, which fits the privacy promise.
14. ~~**3D in CSS, not WebGL.**~~ Superseded by 31: the landing page now uses three.js; the preview, booklet and Trail Book still use CSS 3D.
15. ~~**3D icons from Fluent Emoji.**~~ Superseded by 30: removed.
16. **B&W is the default** because most home printers are mono. Colour mode adds the pink and teal spot colours; B&W swaps fills for hatching.
17. **Pink text uses a deeper "rose" (`#C2295A`)** so it passes WCAG AA on cream; pink buttons use ink text for the same reason.
18. **Demo presets are hand-traced.** The build environment could not reach Overpass, so `scripts/seed-fixtures.ts` traces three real places (Cubbon Park in Bengaluru, Vondelpark in Amsterdam, Dolores Park in San Francisco) in Overpass format and runs them through the real normaliser. `pnpm fixtures:fetch` replaces them with live OSM.
19. **Replays are honest.** Demo replays are recorded per preset and task; until someone runs `pnpm fixtures:record` against Gemma, they're labelled as mock placeholders in the files, and the UI always shows a "replay" badge.
20. **Screen time = visible time only.** The Page Visibility API counts active time per trail (setup is parked under a pending id and adopted when the trail is created). Outside time = photo time − print time, capped at 3 h.
21. **Server is stateless.** No database: trails live in IndexedDB. The server only proxies OSM / weather / geocoding (to cache and send a proper User-Agent) and talks to the model.
22. **Rate limiting is an in-memory token bucket** in middleware (120/min general, 40 burst for model routes) and uploads are capped at 8 MB. Good enough for a demo; put a real limiter in front for anything bigger.
23. **The endpoint override is off by default.** Letting a public page point the server at arbitrary URLs is an SSRF; models can still be switched per browser.
24. **Standalone output only for Docker** (`NEXT_OUTPUT=standalone`), so `pnpm start` works locally and in e2e.
25. **Hosted Gemma, by request.** The owner asked for providers live users don't have to install. `lib/config.ts` supports local Ollama, Ollama Cloud and the Gemini API (plus any OpenAI-compatible endpoint), with a comma-separated fallback chain. Every default model is Gemma, so the zine is still written by open weights. Pointing it at a closed model (e.g. a proprietary Gemini model id) is possible but would break the challenge's "open-source AI at the core" rule.
26. **Capability adaptation instead of per-provider code.** Gemma on the Gemini API takes no system role and no response schema, so those requests fold the system prompt into the user turn and put the JSON schema in the prompt. If any endpoint rejects `response_format` with a 400, the client learns that once and switches to the in-prompt schema.
27. **Generic `LLM_*` vars only configure local/custom endpoints.** A leftover `LLM_BASE_URL` or `LLM_MODEL_TEXT` (e.g. from docker-compose) can't redirect a hosted provider.
28. **Privacy copy follows the provider.** "Your location never left this machine" prints only in local mode; hosted trails name the provider on page 8.
29. **Panels are exact sheet quarters.** The first build offset the grid by the print margin, so a real fold at the sheet's quarter lines missed the panel edges by 3 mm. Margins now live inside each panel (≥ 5 mm from edges and folds); fiducials sit 5 mm in from the corners.
30. ~~**The site is a dark "night walk" design.**~~ Superseded by 33. Warm black, paper that glows like an object under a lamp, one accent (fresh grass green). Fraunces (variable, soft optical sizes) for display, Geist for UI. The emoji icon set was removed: it read as generic clip art. Icons are Lucide line icons, used sparingly.
31. **The landing 3D is three.js, not hosted scenes.** Spline-style scenes load from a third-party CDN at runtime (breaks the privacy rule) and couldn't be authored here anyway. The scene is the real printed sheet as a texture on eight hinged panels: the top row folds back on the long crease and the four columns close as a concertina, so the cover (page 1) ends up on top. Scroll drives it through motion's `useScroll`; function transforms are used because the native ScrollTimeline path mis-maps ranges inside sticky containers. If WebGL is missing or crashes, an error boundary shows the sheet as a still.
32. **rough.js seeds come from shape parameters, not call order**, so server and client (and React StrictMode's double render) draw identical wobbles. The "dots" fill is avoided because rough.js jitters it with an unseeded random.
33. **The site is a light "paper studio".** Bone paper, carbon ink and one riso spot colour (ultramarine `#2B3DD8`), with a dark "darkroom" band (safelight red) only where the photo is read. Instrument Serif for display, Instrument Sans for UI, Fragment Mono for labels, Kalam for transcribed handwriting — self-hosted, OFL. The printed zine keeps its own fonts because its text metrics are generated from those files. The landing 3D is a still life on a shadow-catcher desk (transparent canvas, so only real shadows land on the page), lit for `NeutralToneMapping` so the paper stays white.
34. **The Trail Book is a 3D picture ledge, with an HTML index underneath.** Each zine is a thin block whose cover is its own page 1, rasterised, with the Trail Office stamp inked on. The canvas is decorative (`aria-hidden`); the index list is the accessible, testable way in. Canvases stop drawing frames when scrolled out of view.
35. **The booklet page turn bends.** The turning leaf is a chain of nested CSS 3D strips, each rotated a little past its parent, drawn from pages rasterised once, so the paper curls instead of swinging like a door. It can be dragged by a corner as well as turned with buttons and arrow keys.
36. **The hero fold is a bent sheet, choreographed by anime.js.** One finely divided mesh is deformed every frame: each crease wraps the paper around a small cylinder (`components/landing/foldSheet.ts`), outer creases are rounder so stacked layers wrap instead of intersecting (unit-tested: page 1 on top, eight distinct layers), creases widen and flaps bow while they move. One anime.js timeline holds every track (folds, pose, pencil, captions, hero copy). Its playhead is set from the section's scroll progress each frame with frame-rate-independent damping, rather than anime's own scroll observer, which stops updating 500 ms after the last scroll event and fell behind on slow frames.
37. **The API is designed for a public deploy** (see `docs/api.md`): one error shape with machine codes, request IDs and one JSON log line per request (no coordinates, photos or handwriting), a per-provider circuit breaker so a rate-limited provider is skipped rather than waited on, a FIFO gate on concurrent model calls (503 + Retry-After when the queue wait runs out), client disconnects cancelling model calls, SSE heartbeats, single-flight caches, and a health check cached for a minute so the model badge doesn't spend quota per visitor.
38. **Gemma 4 on the Gemini API thinks unless told not to.** By default it spends its token budget on a `<thought>` preamble and can run out before the answer. Requests send `reasoning_effort: "minimal"` (`GEMINI_REASONING_EFFORT`), and any thought block that still arrives is stripped before parsing. Copy is also checked for leaked internal ids (`n9000024`, `W6`), which real Gemma output did include, and retried.
39. **Everyone gets the hero fold; only the renderer changes.** The fold is one model (`foldSheet.ts` geometry + the `Rig` the anime.js timeline drives) with two renderers that read it: the three.js scene (`StudioScene.tsx`, "high"/"low" detail) and a Canvas 2D one (`LiteScene.tsx` + `liteFold.ts`) that bends the same mesh, projects it through the same camera and draws it as textured cells back to front, ordered along the sheet's own stacking axis (folded layers sit closer than a tilted sheet's depth changes across one row). Lite is picked up front for Data Saver, 2G or no WebGL2, and never downloads three.js. WebGL hands over to it at runtime if the scene throws, loses its context, or a frame-time watchdog sees a median under ~22 fps once the print is on the paper. The flat printed sheet is now only the last resort, if even Canvas 2D throws. Before this, those devices got a still picture.
40. **The hero is fitted to the screen, not to two breakpoints.** The layout is chosen by aspect ratio (`STACKED_QUERY`, mirrored as the CSS `stacked:` variant and kept in step by a test): portrait and square screens stack paper above copy, landscape screens put it beside. Width alone put a 1080 × 1750 portrait tablet in the desktop layout, where the paper was posed off-screen right. The art-directed poses (1280 × 800 and 390 × 844) are now mapped into the regions measured on the live page, the space right of the copy or above the captions, by a uniform scale in screen space projected back through the camera (`components/landing/stage.ts`, unit-tested on fifteen measured screens from 320 × 568 to 3440 × 1440). It re-fits when the hero viewport, copy or captions change size. The pencil's roll-out distance is fitted too. Short screens get a compact hero (the headline is capped at 15svh; on a phone on its side, the label and badge go and the lede goes below 460 px). The lite renderer's shadow no longer borrows `shadowBlur` from a shape drawn off-canvas, which leaked a black slab onto the page whenever the paper sat far from centre: it blurs on-canvas with the canvas filter, or by upscaling a coarse buffer where there is none.
41. **Places never hang on one Overpass server.** The deployed server can't connect to overpass-api.de at all (refused), and the public mirrors flap between 500s and answers within seconds. `/api/places` now fails over between Overpass instances with hedging (a second server is asked if the first is silent for 5 s) and retries transient failures inside a 45 s budget. It also fetches OpenStreetMap vector tiles from OpenFreeMap in parallel as an independent backup: same open data, different servers, free and keyless, and a single tile carries a neighbourhood's streets, water, parks and named places. Google Places was considered and rejected: its terms restrict using its content with non-Google maps and caching it, which is exactly what printing it on our own drawn map does; it needs billing; and the zine promises open OpenStreetMap data. Search-as-you-type uses Photon for the same reason Nominatim isn't used for it: Nominatim's policy forbids autocomplete.
